## 1. 배경과 문제

현재 정규화 기준은 **전체 알파 바운딩박스 높이**(`BODY_SCALE_TARGET_HEIGHT = 111.5`, 128px 캔버스 기준·2배 관례)다.
36장 전부 실측한 결과 현행 값은 전체 실루엣 높이를 거의 완벽히 232px 근처로 맞추고 있다 — 즉 "실루엣 정규화"로서는 정확하다.

문제는 **바운딩박스가 몸통이 아닌 것을 대량으로 포함**한다는 점이다:

| 종족 | bbox에 섞여 들어간 비-몸통 요소 |
|------|-------------------------------|
| bulgeumjo | 머리 위 불꽃(약 26px), 꼬리 불꽃 |
| kong (base) | 김(steam) 약 36px |
| tokki | 긴 귀 + 반짝임 이펙트 |
| seureureuk | 머리 위 유령 불꽃 |
| nyang / kkubeok / ddungsil | 귀, 꼬리, 모자·가방 등 소품 |
| geobujang / nyang_evolved2 | 백팩·캐리어 |
| mundeok | 다리(촉수) 전체 |

그래서 실루엣이 같아도 "실제 몸 덩어리"는 tokki 53px ~ kkubeok 104px로 **2배 차이**가 난다. 사용자가 지적한 체감 크기 불균형의 원인이 이것이다.

## 2. 몸통 정의 (적용한 판정 규칙)

1. **융합형(F)**: 목 경계가 없고 얼굴이 몸 덩어리 위에 직접 그려진 캐릭터. → 뭉쳐진 덩어리 전체를 몸통으로 본다.
2. **분리형(S)**: 머리와 몸통 실루엣이 나뉜 캐릭터(kkubeok, nyang). → 두 값을 모두 실측했다.
   - **엄격 몸통(Metric A)**: 머리 아래 ~ 접지선. 사용자 정의 그대로.
   - **코어 덩어리(Metric B)**: 머리 정수리(귀·모자 제외) ~ 접지선.
3. 제외 대상: 귀, 뿔, 볏, 더듬이, 꼬리, 팔다리·발, 촉수, 김/불꽃/반짝임 이펙트, 사원증·목끈·가방·모자·소품.
4. 측정법: 눈으로 4배 확대 그리드(8px 간격) 위에서 경계 y좌표를 특정 → 돌출부를 피하는 x밴드 안에서 알파(>40) 상/하단을 스크립트로 스캔 → 박스 오버레이를 다시 눈으로 검증. 좌표는 전부 **원본 128px 캔버스 기준**.

### 왜 Metric B를 권장하는가
Metric A를 그대로 쓰면 분리형 2종이 극단으로 커진다. nyang base 엄격 몸통은 40px이라, 융합형 haemjji(96px)와 몸통을 맞추면 nyang의 전체 실루엣이 haemjji의 **2.4배**가 된다. 치비 아트에서 머리는 "부착물"이 아니라 몸 덩어리의 일부로 읽히므로, **분리형도 머리를 포함한 코어 덩어리로 재는 Metric B가 사용자 의도(체감 몸집 균일화)에 더 가깝다.** 아래 BODY_SCALE 제안은 Metric B 기준이며, Metric A 값도 감사 추적용으로 남긴다.

## 4. 새 목표치와 BODY_SCALE 제안

- **새 상수**: `BODY_SCALE_TARGET_TORSO := 80.0` (128px 캔버스 기준 코어 몸통 높이)
  - 근거: 36장 코어 평균 80.5 → 80으로 반올림. 평균을 목표로 잡으면 새 스케일의 평균이 현행 평균(~2.05)과 거의 같아져 **전역 크기 점프가 없다**.

## 5. 옵션 A 적용 시 예상 실루엣 변화 (QA 주의 지점)

현행은 전 캐릭터 실루엣이 균일한 232px. 옵션 A 적용 시 172~290px로 벌어지는데, 이는 **의도된 결과**(몸통을 맞추면 부속물 많은 캐릭터의 실루엣은 커진다)다. 다만 아래는 화면 확인 필수:

| 대상 | 실루엣 232 → | 사유 / 조치 |
|------|-------------|------------|
| **mundeok** 전 티어 | 276 / 284 / 290 | 촉수를 몸통에서 제외했기 때문. 화면에서 과대해 보이면 옵션 B(2.20/2.39/2.38) 사용 |
| **tokki** 전 티어 | 275 / 265 / 273 | 긴 귀 + 반짝임 제외. 위와 동일 |
| **mochi** base/evolved/evolved2 | 173 / 172 / 179 | 납작 블롭이라 코어가 큼 → 축소. 가장 많이 작아지는 캐릭터 |
| **kkubeok** base | 178 | 곰 코어 104px(최대급) → 축소 |
| **kong** evolved | 244 | 컵 포함 판정에 의존. 컵을 소품으로 재판정하면 스케일이 4.8까지 튀므로 **컵 포함 유지 필수** |
| **bulgeumjo** evolved2 | 259 | 불꽃 왕관 제외분이 커서 확대 |

접지선(발바닥) 관련: 이 감사는 **크기(스케일)만** 다룬다. 스케일이 바뀌면 스프라이트 하단 접지 오프셋도 함께 재조정해야 하므로, gd-integrator는 `BODY_SCALE` 반영 후 `scenes/pet/pet.gd`의 발바닥 정렬을 각 종족·티어에서 재확인할 것.

## 6. 재현 방법

측정 스크립트는 스크래치패드에 있고 파라미터(x밴드, y윈도)는 위 표의 y범위와 1:1 대응한다. 재측정 시:
1. 4배 확대 + 8px 그리드 오버레이로 경계 y좌표 육안 특정
2. 돌출부를 피하는 x밴드 안에서 알파>40 상/하단 스캔 (윈도 안쪽이면 스캔값, 판정 경계면 지정값 사용)
3. 빨간 박스 오버레이 렌더 후 육안 재검증

## 7. 후기 (2026-08-07) — 옵션 A 전면 적용 후, 옵션 B를 **2종에만** 부분 적용

### 무슨 일이 있었나

§4 옵션 A(몸통 완전 정규화)를 12종×3티어 전부에 적용했고 헤드리스 테스트는 전부 통과했다
(12종 36조합이 모두 화면상 몸통 72px로 수렴). 그런데 그 상태로 **12종을 adult 기준으로 나란히
렌더해 육안 검증**(비교 스트립 `grid_base_adult.png`)한 결과, §5에서 미리 경고했던 두 캐릭터가
실제로 "혼자 크다"고 읽혔다.

측정 지표는 실루엣 높이가 아니라 **체감 몸집 = 화면상 알파 면적의 제곱근**(adult 기준)이다.
높이만으로는 가로로 퍼진 부속물(촉수·귀)이 잡히지 않아서다. 12종 중앙값은 약 69px:

| 종족 | base / evolved / evolved2 | 중앙값 대비 | 판정 |
|------|---------------------------|------------|------|
| **mundeok** | 104.0 / 104.5 / 108.8 | **약 1.5배 (3티어 전부)** | 과대 — 촉수를 몸통에서 제외한 결과 |
| **tokki** | 84.1 / 83.1 / 85.8 | **약 1.2배** | 과대 — 긴 귀를 몸통에서 제외한 결과 |
| 나머지 10종 | — | 중앙값 ±12% 이내 | 정상, 옵션 A 유지 |

부수적으로 확인한 것 두 가지:
- **mochi**(74.2 / 67.3 / 68.2)는 옵션 A에서 가장 많이 작아지는 캐릭터라 "너무 작지 않나" 우려가
  있었으나 기우였다. 중앙값 근처다. 조치 없음.

### 9.2 조치 — 256px 원본에서 캔버스를 채우도록 재추출

- 목표: idle의 solid bbox 높이를 다른 11종 밴드의 상단인 **113px**에 맞춘다.
- 티어 안에서는 **8포즈 전부 동일한 배율**을 쓴다(포즈 간 상대 크기 보존). idle이 세 티어 모두 최장신 포즈라 idle을 기준으로 잡으면 나머지는 자동으로 113px 이하가 된다.
- 리샘플: **알파 프리멀티플 → LANCZOS 축소 → 언프리멀티플**. 원본 투명부 RGB가 0(검정)이라 스트레이트 알파로 그냥 줄이면 가장자리에 검은 헤일로가 낀다.
- 수평: 캔버스 중심 기준 스케일(`new_x = (old_x-128)*s + 64`) — 원본 구도의 좌우 관계를 그대로 보존한다.
- 수직: 각 포즈의 **solid 최하단이 y=127**이 되도록 평행이동. 하단 여백 0px, 8포즈 접지선 완전 일치(§8.3에서 확보한 성질을 그대로 유지).
- 캔버스는 **128×128 고정** — `pet.gd`의 `STATIC_POSE_SIZE = 128` 전제(1128/1150/1168행의 위치 계산)와 어긋나면 안 된다.

### 9.4 코드 반영값 (gd-integrator 작업분 — 이 문서 작성 시점에는 미반영)

아트가 커진 만큼 `BODY_SCALE`을 낮춰 **화면 렌더 크기를 완전히 동일하게** 유지한다.
배율 보정계수 = 기존 256→128 배율 ÷ 신규 배율 = `0.5 / s`.

| 티어 | 보정계수 | `BODY_SCALE` 기존 → **신규** | `BODY_CORE_HEIGHT` 기존 → **신규** | `expected_torso` 기존 → **신규** | 신규 렌더 배율(×0.45) |
|------|---------|---------------------------|--------------------------------|------------------------------|---------------------|
| base | 0.755162 | 2.735 → **2.065** | 53.0 → **70.2** | 145.0 → **145.0** | **0.929x** |
| evolved | 0.755162 | 2.666 → **2.013** | 55.0 → **72.8** | 146.6 → **146.6** | **0.906x** |
| evolved2 | 0.722347 | 2.840 → **2.052** | 51.0 → **70.6** | 144.8 → **144.9** | **0.923x** |

- `BODY_CORE_HEIGHT`는 아트 실측값이므로 **이번엔 바뀐다**(§8.3에서는 y이동만이라 불변이었다). 신규 코어 높이 = 기존 코어 높이 × (신규 배율 ÷ 0.5) — §2의 몸통 정의(귀·꼬리·반짝임 제외, 융합형이라 덩어리 전체)는 그대로이고 배율만 곱해지므로 선형 환산이 정확하다.
- `expected_torso = BODY_CORE_HEIGHT × BODY_SCALE`가 기존값과 사실상 그대로 나오는 것이 **화면 크기 불변의 산술 증명**이다(±0.1 이내는 반올림 오차).
- `TORSO_NORMALIZATION_EXEMPT["tokki"]`의 예외 근거(발 접지 + 5% 축소, §8.3)는 **유효하다** — 이번 작업은 크기를 바꾸지 않고 픽셀 밀도만 올렸다.

### 9.5 판정

- **성공 기준(렌더 배율 < 1.0) 충족**: 1.231/1.200/1.278x → **0.929/0.906/0.923x**. tokki는 더 이상 12종 중 유일한 확대 렌더가 아니며, kong·seureureuk(0.960)보다도 축소 폭이 크다.
- **화면 크기 불변**: 신규 solid h 113 × 0.929 = 104.6px = 기존 85 × 1.231 = 104.6px (base). 3티어 모두 ±1% 이내.
- **육안 확인**: 기존/신규를 각자의 최종 화면 배율로 렌더해 동일 크기로 놓고 5배 확대 비교. 눈 하이라이트가 뭉개진 얼룩 → 또렷한 원형, 코·입·귀 윤곽선이 번짐 → 선명한 경계, 반짝임 이펙트의 뾰족한 끝이 살아남. 개선 명확.
- **남은 개선 여지(이번 범위 밖)**: `assets/sprites/chars/**/*.png.import` 292개 전부 `mipmaps/generate=false`다. tokki가 이제 baby(0.32)·child(0.38) 단계에서 0.66~0.78배 축소로 렌더되므로 밉맵이 있으면 축소 앨리어싱이 줄어든다. 단 이건 12종 공통 사안이라 tokki만 바꾸면 일관성이 깨진다 — 전 종족 일괄 적용 여부는 별도 판단이 필요하다.

**롤백**: 변경 전 24장 백업은 세션 스크래치패드 `backup128/`에 있고, 256px 원본은 `git show ded469d~1:assets/sprites/chars/tokki*/...`로 언제든 다시 꺼낼 수 있다.

## 10. 후기 (2026-08-07 4차) — tokki 눈 크기 정렬: 캔버스 재추출 배수 상향

작성: sprite-artist / 범위: **아트 24장 재추출 + 코드 반영값 계산만**. GDScript 미수정.

### 10.1 문제

§9로 해상도(선명도)는 복구했지만 사용자 지적: "선명도는 됐는데 크기가 너무 축소되었다.
**눈 크기가 다른 애들과 맞을 정도로** 키워야 한다. 해상도 문제 안 생기게 예전 이미지를 축소하는 식으로."

눈 높이(알파>140 & 휘도<95의 좌우 대칭 블롭) 실측 기준 12종 중앙값은 화면상 **12.48px**
(ddungsil은 실눈이라 제외, n=11). tokki는 원본 눈 12px × 렌더배율 0.929 = **11.15px**로
중앙값 대비 -10.7%, 12종 중 아래에서 두 번째였다. 필요 배수 **×1.1190**.

### 10.2 접근 — BODY_SCALE이 아니라 아트 추출 배수를 올린다

`BODY_SCALE`을 1.119배 하면 렌더 배율이 0.929 → 1.040이 되어 §9에서 겨우 벗어난
**확대 렌더로 되돌아간다**(= 다시 뿌옇게). 사용자가 금지한 방향이다.

대신 **256px 원본에서 캔버스를 더 크게 채우도록 재추출하고 `BODY_SCALE`은 손대지 않는다.**

- 화면상 크기 = 아트 픽셀 × `BODY_SCALE` × `STAGE_SCALE` → 아트가 1.119배면 화면도 1.119배
- 렌더 배율 = `BODY_SCALE` × `STAGE_SCALE` → **불변**(0.929/0.906/0.923, 전부 축소 유지)

재추출 방법은 §9.2와 완전히 동일하다(알파 프리멀티플 → LANCZOS → 언프리멀티플 /
티어 내 8포즈 동일 배수 / solid 최하단 y=127 / 캔버스 128×128 고정). 바뀐 것은 배수뿐이다.

### 10.3 난점 — 세로·가로 여유가 없어서 분리 이펙트를 제거했다

목표 배수(base/evolved 0.740900, evolved2 0.774558)를 그대로 적용하면 24장 중 다수가
캔버스 밖으로 잘렸다. 제약을 실측해 보니 **귀나 몸통이 아니라 "몸에서 떨어져 떠 있는 이펙트"가
바운딩박스를 부풀리고 있었다**:

- 4각 반짝임(sparkle), 하트, 음표, 모션 스우시, sleep 포즈의 "z" 글자
- 1~5px짜리 먼지 픽셀 수십 개(walk1 23개, sulk 32개 등)

예: base walk1의 몸통은 x 94~204인데 x=41에 떠 있는 103px 반짝임 하나 때문에 가로 폭이
170px으로 잡혀 배수가 0.7356으로 묶였다. evolved eat은 y=23의 떠 있는 반짝임 때문에
세로 배수가 0.7017까지 내려갔다.

제작 가이드 §2는 **분리된 이펙트·텍스트를 금지**한다(ppiyak 작업에서 확립). tokki는 그 규칙
이전 자산이라 남아 있던 것이므로, **24장 전부에서 최대 연결요소(=몸통+들고 있는 소품+붙어 있는
오라)만 남기고 분리 컴포넌트를 전부 제거**했다. 가이드 위반 해소와 공간 확보를 동시에 달성한다.

| evolved | 52 ~ 911px (블롭 4~12개) |

**몸에 붙어 있는 노란 오라/꼬리 광채는 최대 연결요소에 포함되므로 그대로 남아 있다.**

## 10.7 후속 조치 (2026-08-07 5차) — tokki 이펙트 잔해 제거

### 문제

§10.3의 "최대 연결요소만 남기기"가 **덜 지웠다.** 반짝임·스우시가 몸통과 **희미한 알파(대략 65~140)로
이어져 있으면** 최대 연결요소 판정에 통째로 딸려 들어와 살아남는다. 실제로 `tokki/idle`을 5배
확대하면 x24~45 / y67~99에 442px짜리 노란 얼룩(잘려나간 반짝임 덩어리)이 남아 있었다. 알파>64
기준 연결요소 분석에서는 이 파일이 "CLEAN"으로 나오는데, 알파>140으로 다리를 끊으면 별도
컴포넌트로 분리된다 — 즉 **연결성 임계가 낮았던 것이 근본 원인**이다.

### 검출·제거 방법 (색상 기반 시드 + 근접 보존)

좌표 하드코딩이 아니라 **색상으로 이펙트를 정의하고 몸통을 재구성**했다.

1. `yellow = (R-B ≥ 65) & (R ≥ G) & (G ≥ 0.72R) & (R ≥ 110)` — 반짝임/스우시의 채도 있는
   연노랑. 몸통 크림(R-B ≈ 20), 당근 주황·발(G/R ≈ 0.58), 빨간 머리띠, 초록 샐러드볼(G>R),
   파란 목도리·보라 쿠션(R-B<0)은 전부 이 조건을 통과하지 못한다.
2. `seed = ((알파 > 120) & ~yellow)의 최대 8-연결요소` — 이펙트 픽셀을 **시드에서 먼저 빼기**
   때문에 희미한 알파 다리로는 다시 붙을 수 없다.
3. `keep = seed를 반경 3px 팽창한 영역 ∩ (알파>0)` — 몸 윤곽의 노란 림라이트와 안티에일리어싱은
   이 3px 안에 들어와 보존된다. 그 밖은 전부 0으로 지웠다(RGB도 0으로 해 프리멀티플 잔상 방지).

시도했다가 **기각한** 방법: (a) 모폴로지 열림(erode 2) — 귀·발이 절단됨. (b) 히스테리시스
(느슨한 노랑으로 영역 성장) — 크림 몸통으로 번져 몸에 구멍이 생김. 두 경우 모두 확대 육안 검수에서
바로 걸러냈다.

- **PROTECT** `tokki/eat` x100~116,y58~94 — 이 포즈의 엉덩이 실루엣 자체가 R-B 중앙값 50으로
  따뜻해서 전역 규칙이 4~6px 파먹었다(실루엣이 오목해짐). 고정해서 복원.

### 11.2 새 방침 — 원본 픽셀을 삭제·수정하지 않는다

## 12. 후기 (2026-08-07 7차) — evolved / evolved2 24티어 192장 해상도 복구 (256px 원본)

### 12.1 문제

12종 x 3티어 화면 렌더 배율 실측 결과 **진화 티어 4종이 이미 확대(업스케일) 렌더** 상태였다.
확대는 원본에 없는 픽셀을 보간으로 만들어내므로 뿌옇게 보인다 — §9에서 tokki(1.23배)를
"해상도가 안 좋아 보인다"고 지적받았던 것과 같은 결함이다.

| 대상 | 당시 렌더 배율 |
|---|---|
| kong / evolved | **1.22x** |
| bulgeumjo / evolved2 | 1.14x |
| ppiyak / evolved2 | 1.01x |
| ddungsil / evolved2 | 1.01x |

원인은 `ded469d`("Halve source resolution of all character sprites")가 전 캐릭터 원본을
256->128px로 줄이면서, 캔버스를 덜 채우는 진화 티어 아트가 확대 렌더로 뒤집힌 것이다.
추가로 크기 사다리(base 108 / evolved 118 / evolved2 128)를 얹으면 확대가 8종·최대 1.35배로
악화된다. 256px 복원이 두 문제를 동시에 해결한다.

### 12.2 원리 — 원본을 확대하지 않는다

256px 원본에서 캐릭터 몸이 차지하는 픽셀은 약 170px, 화면에 그려지는 크기는 100~120px이다.
**256px 원본을 그대로 쓰면 축소 렌더(약 0.42~0.81배)가 되어 선명하다.** 128px 파일들은 그
170px을 85px로 버려놨기 때문에 확대가 필요해진 것이다. 따라서 캔버스 여백이 남아도
**원본을 확대해 채우지 않았다.** 허용 연산은 평행이동과 (필요시) 축소뿐이다.

### 12.3 적용한 변환

- 소스: `git show ded469d~1:assets/sprites/chars/{티어}/{포즈}.png` (전부 256x256 RGBA, 192/192장 존재).
- 출력 캔버스 256x256. **스케일 없음 — 192장 전부 순수 평행이동만 적용했다.**
  사전 실측에서 "강한 픽셀(알파>=200) 상단 ~ solid(알파>128) 하단" 높이와 강한 픽셀 폭이
  256을 넘는 포즈가 **한 장도 없었으므로**, 접지 이동만으로 잘림이 발생하지 않았다.
  **축소를 적용한 파일은 0장이다.**
- 수직: 포즈별 `dy = 256 - solid_bbox.bottom` -> solid 최하단이 y=255. 하단 여백 0px.
- 수평: **티어 안 8포즈 공통 `dx`** (상대 위치 보존). 선호값은 티어 solid 합집합 중심을
  x=128에 맞추는 값이고, 8포즈 전부의 강한 픽셀이 [0,256] 안에 남는 범위로 클램프했다.
  적용된 dx는 -2 ~ +9 범위(과반이 0)로 작았다.
- **원본 픽셀 삭제·수정 없음.** §10.7->§11의 사고(이펙트 제거 시도 -> 몸통 찢김)를 반복하지
  않기 위해 색상 시드 분리를 일절 쓰지 않았다.
- `.import` 파일은 손대지 않았다(기존 것 유지, 밉맵 설정 이번 범위 밖).

### 12.4 solid 판정은 알파>128 — raw 알파(>0)를 쓰지 마라

직전 작업의 교훈을 그대로 적용했다. raw 알파(>0) bbox로 정렬하면 몸통에서 떨어진
알파 1~3짜리 크로마키 잔여 점이 bbox를 부풀려 접지가 어긋난다. **정렬 기준은 알파>128,
무잘림 검증 기준은 알파>=200**으로 분리했다.

### 12.8 육안 검수 (수치만으로 통과시키지 않았다)

현재 뿌옇던 4종 + tokki 2티어를 **같은 화면 크기로 정규화한 뒤 3배 NEAREST 확대**해
좌(구 128px) / 우(신 256px)로 나란히 비교했다:
kong/evolved, bulgeumjo/evolved2, ppiyak/evolved2, ddungsil/evolved2, tokki/evolved, tokki/evolved2.

- kong/evolved: 커피잔 라떼아트 결·눈 하이라이트가 뭉개져 있던 것이 또렷해졌다.
- bulgeumjo/evolved2: 머리 불꽃의 그라데이션 띠와 깃털 경계가 분리돼 보인다.
- ppiyak/evolved2: 볏·꼬리 깃털 결과 명찰 글자가 살아났다.
- ddungsil/evolved2: 줄무늬 털결과 지폐/금괴 디테일이 복원됐다.
- tokki/evolved·evolved2: 털결·머리띠·그릇 안 야채가 선명해졌다.
- **화면상 크기는 전부 유지**(비교 시 표시 크기 171/170, 173/172, 154/152, 154/154px 등).

192장 전체 컨택트시트(포즈별 8열 x 24티어행, 접지선 오버레이)로 찢김·구멍·잔해·접지 이탈을
전수 확인했고 이상 없음.

### 12.9 다음 사람에게 / 롤백

- **base 티어(`{species}/`)는 이번 작업에서 건드리지 않았다.** base는 최대 0.96배로 확대가
  없고 사용자가 현재 크기를 승인했다. base까지 256px로 올리려면 같은 절차를 별도로 밟아라.

  **이번 작업에서 수정하지 않았다** — §12.5 표를 gd-integrator가 반영한다. 반영 전까지는
  아트만 2배 커진 상태이므로 진화 티어가 화면에서 약 2배로 보인다(의도된 중간 상태).

  `backup128/assets/sprites/chars/{티어}/{포즈}.png`.
  256px 소스는 `src256/assets/sprites/chars/...` 및 `git show ded469d~1:...`.

  검수 이미지는 `compare.png`(6종 전/후 3배 확대)와 `allnew.png`(192장 컨택트시트).
