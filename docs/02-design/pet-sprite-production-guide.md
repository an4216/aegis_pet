# 펫 스프라이트 제작 기준 — 비숑 완성본

> 이 문서는 현재 서비스의 **아기 비숑 완성본**을 기준으로, 다음 캐릭터를 제작하거나 기존 캐릭터를 보정할 때 사용하는 실무 기준이다. 이 프로젝트는 상태별 개별 스프라이트 시트를 사용하는 Godot 런타임 계약이며, 다른 형식의 단일 대형 아틀라스 규격과 혼용하지 않는다.

## 1. 기준 자산과 단일 진실 공급원

| 구분 | 위치 | 용도 |
|---|---|---|
| 런타임 비숑 시트 | `assets/sprites/bichon/` | 서비스에서 실제로 읽는 완성 자산. 덮어쓰지 말고 새 캐릭터는 별도 폴더를 쓴다. |
| 애니메이션 계약 | `scenes/pet/pet.gd`의 `BICHON_ANIMATIONS` | 시트 경로, 그리드, 논리 프레임, FPS, 반복, 크기·위치 보정의 단일 진실 공급원. |
| 회귀 검증 | `tests/bichon_animation_integration.gd` | 기준선, 중심, 양쪽 경계, 크기, 파일 먹기, 렌더 필터를 검증한다. |
| 최종 앉은 Idle 제작 기록 | `assets/generated/sprites/bichon-seated-idle-v1/` | 현재 Idle의 선택·구성·QA 기록. 참고용 원본이며 런타임은 위의 `assets/sprites/bichon/` 자산을 읽는다. |

## 2. 비숑 완성본에서 지킨 시각적 원칙

### 캐릭터 아이덴티티

- 아기 비숑의 둥근 흰 털 실루엣, 검은 눈·코, 짧은 다리와 부드러운 베이지 음영을 모든 상태에서 유지한다.
- 표정, 귀, 꼬리, 털 질감의 변화는 동작을 설명하는 만큼만 사용한다. 상태가 바뀌어도 다른 캐릭터처럼 보일 정도의 비율·색·얼굴 변화는 허용하지 않는다.
- 배경은 투명 알파를 우선한다. 크로마키로 제작했다면 알파로 깔끔하게 변환하고, 반투명 가장자리·투명 영역에 키 색이 남지 않았는지 확인한다.
- 바닥 그림자, 분리된 이펙트, 배경 소품, 텍스트는 넣지 않는다. 동작 의미는 몸·얼굴·발·꼬리의 포즈만으로 읽혀야 한다.

### 화면 위의 물리감

- 모든 동작의 발바닥은 Windows 작업표시줄 **바로 위 기준선**에 닿는다. 프레임마다 몸이 위아래로 튀거나 공중에 뜨면 실패다.
- 걷기를 제외한 모든 동작은 몸통 중심을 고정한다. 팔·귀·꼬리 등 필요한 부위만 움직이고, 프레임 교체 때문에 캐릭터 전체가 좌우로 흔들리면 안 된다.
- 걷기만 보행 감각을 위해 원본의 작은 수평 이동을 유지할 수 있다. 이동 방향은 시트의 기본 방향과 `flip_h`의 의미를 실제 화면에서 모두 확인한다.
- 가장 넓은 자세도 성체 크기에서 화면 좌우에 잘리지 않아야 한다. 실제 이동 범위는 스프라이트 반폭과 안전 여백을 함께 고려한다.
- 동작별 캔버스 여백이 달라도 눈에 보이는 몸통 크기는 일관되어야 한다. 특히 쓰다듬기(`Pet`)의 몸통 크기는 Idle과 같게 맞춘다.

### 부드러운 렌더링

- 비숑은 큰 원본 시트를 축소해 보여 주므로 `CanvasItem.TEXTURE_FILTER_LINEAR_WITH_MIPMAPS`를 사용한다.
- 각 런타임 비숑 PNG의 `.import`에는 `mipmaps/generate=true`가 필요하다. 밉맵 없는 선형 축소는 털 윤곽에 계단 현상을 만든다.
- 의도적으로 픽셀아트를 쓸 새 캐릭터라면 이 기준을 무심코 `Nearest`로 바꾸지 않는다. 현재 서비스 크기에서 정수 배율로 표시할 별도 설계가 없는 한, 같은 선형+밉맵 방식을 유지한다.

## 4. 새 캐릭터 제작 절차

### 4.1 시트 제작 전 캐릭터 시트에 먼저 적을 것

1. **정면/기본 실루엣**: 머리·몸통·발의 비율, 눈·입·귀·꼬리·대표 색을 한 장의 기준 포즈로 확정한다.
2. **기준 발바닥선**: 모든 프레임에서 화면 바닥에 닿는 동일한 발바닥/몸체 하단 위치를 정한다. 앉거나 눕는 동작도 최저 접지점을 정한다.
3. **고정 부위와 가동 부위**: Idle/반응 동작에서는 몸통을 고정하고 어느 부위만 움직일지 정한다. 걷기만 수평 보행을 허용한다.
4. **최대 폭·높이 자세**: 귀·꼬리·팔을 편 프레임을 미리 정해 캔버스와 화면 경계 안전 여백을 확보한다.
5. **표정 언어**: Idle의 미세 표정, 먹기 전 열린 입, 먹기, 아픔, 시무룩함, 쓰다듬기, 놀이의 차이를 작은 크기에서도 구별할 수 있게 설계한다.

### 4.2 자산 구성 규칙

- 새 캐릭터는 `assets/sprites/<character_id>/`에 상태별 PNG를 둔다. 파일명은 `<state>_<frames>f_alpha.png` 또는 기존 호환용 `<state>_<frames>f_chromakey.png`처럼 상태와 논리 프레임 수가 보이게 한다.
- 한 시트 안에서는 격자 칸의 폭·높이를 일관되게 한다. 신규 시트는 가능하면 전체 이미지 크기를 열·행 수로 나누어떨어지게 내보낸다. 기존처럼 나누어떨어지지 않는 원본을 물려받았다면 Godot에서 실제 분할과 외곽 잘림을 먼저 검증하고 그 값을 고정한다.
- 큰 원본에서 축소 렌더링해도 좋지만, 각 상태의 **보이는 몸통 크기**를 기준으로 정규화한다. 빈 투명 여백이나 시트 전체 픽셀 크기를 크기 기준으로 쓰지 않는다.
- 포즈마다 캔버스를 임의로 옮기지 않는다. 몸통 중심과 발바닥선을 원본 단계에서 맞춰 두고, 불가피한 차이만 런타임 보정값으로 기록한다.
- 동작 하나를 손볼 때는 같은 시트의 모든 프레임을 함께 점검한다. 한 프레임만 다른 몸통 크기·윤곽·조명·배경을 갖게 고치지 않는다.

### 4.3 런타임 등록 계약

새 캐릭터의 상태별 설정은 `scenes/pet/pet.gd`와 같은 형태의 애니메이션 맵에 등록한다. 각 상태에는 다음 항목이 필요하다.

| 항목 | 역할 | 검증 기준 |
|---|---|---|
| `path` | 런타임 PNG 경로 | 파일과 `.import`가 존재한다. |
| `columns`, `rows` | 시트 격자 | 실제 시트 분할과 일치한다. |
| `frames`, `fps`, `loop` | 논리 재생 계약 | 논리 프레임 수가 의도한 루프/반응 길이와 일치한다. |
| `visible_extent` | 보이는 몸통 기준 크기 | 각 상태를 같은 화면상 몸통 크기로 맞춘다. |
| `foot_padding` | 프레임별 세로 접지 보정 | 반드시 논리 프레임 수와 같은 길이이며, 모든 프레임이 작업표시줄선에 닿는다. |
| `horizontal_offsets` | 프레임별 가로 몸통 중심 보정 | Walk 외 상태는 반드시 논리 프레임 수와 같은 길이여야 한다. 좌우 반전 시 부호도 함께 뒤집힌다. |
| `sprite_frame_sequence` | 시트 셀 재사용/지연 | Idle처럼 적은 칸으로 긴 정지·깜박임 루프를 만들 때만 쓴다. |

현재 코드의 크기 계산은 `visible_extent`를 기준으로 하며, 기본적으로 `256 × 캐릭터 가시 크기 배수 ÷ visible_extent`에 성장 단계 배율을 곱한다. 새 캐릭터는 비숑의 `1.25`를 무조건 복사하지 말고, Idle·Pet·Walk의 실제 화면상 몸통 높이를 비교해 그 캐릭터에 맞는 가시 크기 배수를 결정한다.

## 5. 동작별 제작 지침

| 동작 | 반드시 지킬 점 |
|---|---|
| Idle | 일어서서 호들갑스럽게 움직이지 않는다. 앉거나 캐릭터다운 휴식 자세를 유지하고, 깜박임 같은 짧은 미세 변화만 둔다. |
| Walk | 기본 시트가 어느 쪽을 향하는지 명시한다. 반전한 반대 방향까지 검수한다. 발바닥은 프레임마다 기준선에 붙고, 보폭은 자연스럽게 교대한다. |
| Sleep | 잠드는 포즈를 즉시 재생하지 않는다. 상태 로직이 가장자리까지 이동한 다음 Sleep 시트로 바뀌는 흐름을 유지한다. |
| Eat | 입·머리·앞발 움직임으로 씹는 느낌을 준다. 몸 전체가 좌우로 미끄러지지 않게 한다. |
| FileHover / FileConsume | 호버에는 열린 입을 명확히 보여 주고, 드롭 뒤에는 별도의 비반복 섭취 시트를 재생한다. 두 시트 모두 같은 기준선·몸통 크기를 사용한다. |
| Pet / Play | 감정은 크게 읽히되, 몸통 크기와 접지 위치는 Idle과 맞춘다. |
| Sick / Sulk / Poop | 감정·상태의 차이는 얼굴과 자세로 구분한다. 분리된 장식, 배경, 그림자로 의미를 대신하지 않는다. |
| Dragged / Fall / Land | 넓은 실루엣이 되기 쉬우므로 좌우 안전 여백을 먼저 확인한다. 착지 후 기준선 복귀이 자연스러워야 한다. |

## 6. 완료 전 체크리스트

### 정적 점검

- [ ] 모든 런타임 PNG는 투명 배경이거나 깨끗하게 투명화 가능한 단색 배경이다.
- [ ] 시트의 열·행, 논리 프레임 수, FPS, 반복 여부가 코드 설정과 일치한다.
- [ ] 모든 상태에 양수 `visible_extent`가 있고, 각 논리 프레임마다 `foot_padding`이 있다.
- [ ] Walk 외 상태에는 프레임 수와 같은 길이의 `horizontal_offsets`가 있다.
- [ ] Idle의 긴 정지 구간은 동일 셀 재사용으로 구현해도 되지만, 깜박임 프레임은 분명히 다르다.
- [ ] 큰 원본을 축소하는 모든 런타임 자산은 밉맵을 생성하고 선형+밉맵 필터를 사용한다.

### 실제 화면 QA

- [ ] baby와 adult 모두에서 모든 프레임의 발바닥이 작업표시줄 바로 위 기준선에 맞는다.
- [ ] Walk를 제외한 동작의 몸통 중심이 프레임마다 좌우로 흔들리지 않는다.
- [ ] Walk는 왼쪽·오른쪽 모두 올바르게 향하고, 프레임 순서가 역재생되지 않는다.
- [ ] Idle은 앉은/휴식 자세로 유지되며, 눈 깜박임 외 불필요한 상하 바운스가 없다.
- [ ] Idle, Pet, Play, Eat 사이의 몸통 크기가 눈에 띄게 달라지지 않는다.
- [ ] Sleep은 가장자리까지 걸어간 뒤에만 Sleep으로 전환된다.
- [ ] 파일을 캐릭터에 호버하면 FileHover, 놓으면 FileConsume, 종료 후 이전 상태로 돌아간다.
- [ ] 가장 넓은 프레임도 성체 크기 화면의 양쪽 끝에서 잘리지 않는다.
- [ ] 실제 표시 크기에서 윤곽이 계단지거나 과도하게 흐리지 않다.
